ThreatAttest Identity Module Implementation

Complete implementation guide for x/identity, compliance tiers, attester identity fields, and browser extension DNS identity badges.

Overview

This document covers the four components implemented in this session:

  1. x/identity module — full Cosmos SDK module scaffolding for DNS-anchored signer identities
  2. attester_domain / attester_selector fields — cross-reference attestations to the attester's DNS identity
  3. Browser extension DNS identity badges — show verified attester identity in the ThreatAttest Shield popup
  4. Compliance tier enforcement — scale attestation confidence by the attester's tier (0.25×–2.00×)

All four components build directly on the DNSSEC-Anchored Signer Identity Protocol Specification (TAT-IDP-001).

x/identity — Types

DNSIdentityRecord

The canonical on-chain "identity block" stored at idrecord/{cosmosAddr}.

type DNSIdentityRecord struct {
    IdentityID        string       // SHA-256(cosmosAddr|"|"|domain|"|"|registeredAt)
    CosmosAddr        string       // Cosmos bech32 address
    Domain            string       // Normalized domain name
    Selector          string       // DNS selector
    PublicKeyHex      string       // Compressed secp256k1 pubkey (66 hex chars)
    Name              string       // Human-readable name (optional)
    URI               string       // Identity URI (optional, https://)
    Flags             IdentityFlag // Bitmask: EXPERT, ORGANIZATION, GOVERNMENT, ...
    Status            DNSIDStatus  // PENDING|ACTIVE|EXPIRED|REVOKED|DNS_REMOVED|SUPERSEDED
    RegisteredAt      int64        // Unix timestamp (immutable)
    LastVerifiedAt    int64        // Unix timestamp of last DNS re-verification
    ExpiresAt         int64        // Unix timestamp of expiry
    DomainProofSig    string       // ECDSA signature (128 hex chars)
    Evidence          DNSEvidenceBundle
    AttestationID     string       // Cross-ref to TATST:IDENTITY attestation
    RegisteredAtBlock int64
    PreviousSelector  string       // Populated during key rotation
    RotatedAt         int64
    RevocationNotes   string
    SchemaVersion     int
}

DNSIDStatus Lifecycle

x/identity — CLI Reference

Transaction Commands

# Register identity
threatattestd tx identity register-identity \
  --domain example.com \
  --selector tat2025a \
  --pubkey 02a1b2c3d4e5f6... \
  --domain-proof-sig aabbccdd... \
  --evidence-file evidence.json \
  --name "Example Corp Security" \
  --uri https://security.example.com \
  --from mykey --chain-id threatattest-1

# Rotate key (DKIM-style dual-selector handoff)
threatattestd tx identity rotate-identity-key \
  --new-selector tat2025b \
  --new-pubkey 03d4e5f6... \
  --rotation-auth-sig aabbcc... \   # signed by CURRENT key
  --new-key-proof-sig ddeeff... \   # signed by NEW key
  --evidence-file new_evidence.json \
  --from mykey --chain-id threatattest-1

# Revoke identity (permanent)
threatattestd tx identity revoke-identity \
  --reason "Key compromise" \
  --from mykey --chain-id threatattest-1

# Renew identity (extend TTL + refresh evidence)
threatattestd tx identity renew-identity \
  --evidence-file fresh_evidence.json \
  --from mykey --chain-id threatattest-1

Attestation Changes — attester_domain / attester_selector

Two optional fields have been added to MsgPublishAttestation and AttestationRecord:

FieldTypeDescription
attester_domainstringNormalized domain of the attester's DNS identity. When set, the attestation is cross-referenced to the identity record at idrecord/{attester}.
attester_selectorstringDNS selector for the attester's active TAT key record at publish time.
attester_tierint32 (record only)Compliance tier (0–3) at publish time. Stored in the record; not a message field.

CLI Usage

threatattestd tx attestation publish-attest \
  --artifact-type DOMAIN \
  --raw-value malware.example.net \
  --category TATST:MALWARE \
  --confidence 90 \
  --attester-domain myresearch.org \       # NEW: your DNS identity domain
  --attester-selector tat2025a \           # NEW: your active selector
  --from mykey --chain-id threatattest-1

Validation Rules

  • Both fields are optional. If one is set, the other is required.
  • attester_domain must be a valid normalizable domain name.
  • attester_selector must be a valid DNS label (≤63 chars, alnum+hyphen).
  • The keeper does not (currently) verify that the identity record exists at publish time — this is a stateless check. Stateful cross-reference verification is a production enhancement.

Attestation Changes — Tier-Scaled Confidence

When an attestation is published, the raw confidence value is automatically scaled by the attester's compliance tier multiplier before being stored on-chain.

// In x/attestation/keeper/msg_server.go:
attesterTier := s.identityTier(ctx, msg.Attester)
scaledConfidence := applyTierToConfidence(msg.Confidence, attesterTier)

// Formula: scaled = raw * numerator / 4, clamped to [0, 100]
// Tier 0 (ANONYMOUS): raw * 1/4  → max 25
// Tier 1 (STAKED):    raw * 2/4  → max 50
// Tier 2 (DNS_BOUND): raw * 4/4  → unchanged
// Tier 3 (EXPERT):    raw * 8/4  → clamped to 100
The identityTier() function currently returns 0 (ANONYMOUS) as a stub. To enable live tier scaling, inject the x/identity keeper into x/attestation's MsgServer at app.go wiring time (see App Wiring).

Browser Extension — Identity Badge

The ThreatAttest Shield popup now displays a DNS identity badge for the current tab's domain. The badge is powered by dns_identity.js which fetches identity records from the chain REST API and caches them in memory.

Cache Behaviour

  • Positive (found) entries cached for 5 minutes
  • Negative (not found) entries cached for 2 minutes
  • Cache invalidated on navigation to a new domain
  • Background prefetch fires on every navigation (fire-and-forget)

App Wiring — Integration Guide

To wire the x/identity module into your Cosmos SDK app (app/app.go):

// 1. Instantiate the identity keeper
app.IdentityKeeper = identitykeeper.NewKeeper(
    keys[identitytypes.StoreKey],
    appCodec,
    app.BankKeeper,
    app.StakingKeeper,
)

// 2. Register the module in ModuleManager
app.ModuleManager = module.NewManager(
    // ... existing modules ...
    identity.NewAppModule(app.IdentityKeeper),
)

// 3. Add identity store key
app.MountKVStores(keys)  // keys must include identitytypes.StoreKey

// 4. Wire identity tier lookup into attestation's MsgServer
// (add IdentityTierKeeper interface to attestation's MsgServer struct
//  and inject app.IdentityKeeper here)

// 5. Add identity module to BeginBlockers/EndBlockers order
// EndBlock: identity module processes expired records

DNS Evidence Collection Script

#!/bin/bash
# scripts/collect_evidence.sh — collect DNSSEC evidence bundle for registration
# Usage: ./collect_evidence.sh example.com tat2025a > evidence.json

DOMAIN=$1; SELECTOR=$2
FQDN="${SELECTOR}._tatkey.${DOMAIN}"
RESOLVER="8.8.8.8"  # Use a DNSSEC-validating resolver

python3 - <<'PYEOF'
import json, subprocess, sys, time

domain = sys.argv[1] if len(sys.argv) > 1 else ""
selector = sys.argv[2] if len(sys.argv) > 2 else ""
fqdn = f"{selector}._tatkey.{domain}"

bundle = {
    "txt_records": [],
    "txt_rrsigs": [],
    "zone_dnskeys": [],
    "dnskey_rrsigs": [],
    "parent_ds": [],
    "collected_at": int(time.time()),
    "resolver": "8.8.8.8"
}

# Use dig to collect records (production: use miekg/dns Go resolver)
for rtype in ["TXT", "RRSIG TXT", "DNSKEY", "RRSIG DNSKEY"]:
    result = subprocess.run(
        ["dig", "+dnssec", "+noall", "+answer", f"@8.8.8.8", fqdn, rtype],
        capture_output=True, text=True
    )
    bundle["txt_records" if "TXT" in rtype else "zone_dnskeys"].append(result.stdout)

print(json.dumps(bundle, indent=2))
PYEOF
