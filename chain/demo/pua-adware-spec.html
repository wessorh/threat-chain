PUA, Phishing URL & Advertising Attestations

Publish on-chain attestations for Potentially Unwanted Applications (PUA), specific phishing URLs, entire phishing site domains, adware distribution domains, and malvertising networks — with rich metadata and artifact-type enforcement.

Overview

ThreatAttest v1.1 extends the attestation schema with three new threat intelligence domains that were previously underserved by the original category set:

⚠️

PUA — Potentially Unwanted Application

Software that is not outright malicious but exhibits unwanted, deceptive, or privacy-invasive behaviour: bundled adware, browser hijackers, fake AV tools, registry cleaners, toolbars, etc.

FILE artifact
🎣

Phishing URL & Phishing Site

Specific URLs serving phishing content (PHISHING_URL) or entire domains operated as phishing platforms (PHISHING_SITE). Complements the original TATST:PHISHING category with finer-grained typing.

URL or DOMAIN artifact
📢

Adware & Malvertising

Domains and URLs that deliver intrusive or deceptive advertising (ADWARE) or serve as malvertising infrastructure that distributes malware through ad creatives or exploit-kit redirects (MALVERTISING).

URL or DOMAIN artifact

A new DOMAIN artifact type (4) is introduced alongside the existing FILE (1), URL (2), and IPV4 (3) types. It allows attesting an entire domain name — rather than a specific URL — as the artifact, which is the natural representation for adware CDN domains, phishing-site operators, and malvertising networks where the threat is domain-scoped rather than path-specific.

New Threat Categories

Category Code Icon Label Valid Artifact Types Typical Severity Description
TATST:PUA ⚠️ PUA FILE LOW – MEDIUM Potentially Unwanted Application. Executable / installer that exhibits unwanted behaviour without being fully malicious.
TATST:PHISHING_URL 🎣 Phishing URL URL DOMAIN HIGH A specific URL path that serves a phishing page or redirects to one.
TATST:PHISHING_SITE 🎣 Phishing Site URL DOMAIN HIGH The entire domain is operated as a phishing platform, regardless of specific path.
TATST:ADWARE 📢 Adware URL DOMAIN LOW – MEDIUM Domain or URL that distributes adware, browser-hijacking software, or serves intrusive advertising without clear user consent.
TATST:MALVERTISING 🎯 Malvertising URL DOMAIN MEDIUM – HIGH Advertising network domain or landing URL used to distribute malware through ad creatives, forced redirects, or exploit-kit delivery.
ℹ️
Backward compatibility The original TATST:PHISHING category remains valid and unconstrained. The new PHISHING_URL / PHISHING_SITE categories provide additional specificity — you can combine them: ["TATST:PHISHING", "TATST:PHISHING_SITE"] on a DOMAIN artifact is valid and encouraged when both classifications apply.

DOMAIN Artifact Type (4)

The ArtifactType_DOMAIN = 4 enum value represents a bare, normalised domain name as the attested artifact. The SHA-256 is computed over the normalised domain bytes, not over a full URL.

When to use DOMAIN vs URL

ScenarioArtifact Typeraw_value
Specific phishing path: https://evil.com/login/paypal URL Full URL string
Entire phishing domain: evil.com DOMAIN Bare domain: evil.com
Adware CDN endpoint: https://cdn.shady.com/ad.js URL Full URL string
Adware distribution domain: shady.com DOMAIN Bare domain: shady.com
C2 domain (any subdomain malicious) DOMAIN Apex or subdomain

Domain Normalization

The canonical form is computed by types.NormalizeDomain():

// Normalization steps (applied in order):
1. Lowercase the entire input
2. Strip any scheme prefix (http://, https://)
3. Strip any path, query string, or fragment
4. Strip any port number
5. Strip leading "www." prefix
6. Validate: must have ≥ 2 labels, each label 1-63 chars

// Examples:
"www.Evil.Example.COM"  → "evil.example.com"
"https://ads.cdn.evil.com/path?q=1"  → "ads.cdn.evil.com"
"PHISHING-SITE.biz:443"  → "phishing-site.biz"

SHA-256 Computation

// artifact_sha256 = hex(SHA-256(normalizedDomain_UTF8_bytes))
normDomain, _ := types.NormalizeDomain("evil-ads.cdn.example")
// normDomain = "evil-ads.cdn.example"
sha256hex := types.ArtifactSHA256ForDomain(normDomain)
// sha256hex = hex(SHA-256(b"evil-ads.cdn.example"))
⚠️
raw_value is required for DOMAIN artifacts Unlike FILE artifacts where raw_value is optional, DOMAIN attestations require raw_value to be set to the domain string. The keeper verifies that artifact_sha256 == SHA-256(NormalizeDomain(raw_value)).

PUA — Potentially Unwanted Application

A Potentially Unwanted Application (PUA) is software that, while not technically malware in the traditional sense, exhibits behaviour that most users would consider undesirable, deceptive, or harmful to privacy. Common examples include:

  • Browser hijackers — change homepage, default search engine, or new-tab page without clear consent
  • Fake AV / scareware — tools that report false positives to coerce purchase of a "full version"
  • Bundled adware — legitimate software that silently installs advertising components
  • Unwanted toolbars — browser extensions bundled with free software installers
  • Deceptive registry cleaners — tools claiming to fix fabricated Windows registry issues
  • Covert cryptominers — CPU/GPU miners installed without explicit user knowledge
  • Data-harvesting freeware — software that sells user behaviour data without meaningful disclosure

PUA Constraint: FILE artifacts only

The TATST:PUA category is constrained to ArtifactType_FILE. This is because PUA describes the behaviour of an executable or installer — a binary artifact with a concrete SHA-256. If you want to attest a domain that distributes PUA, use TATST:ADWARE on a DOMAIN artifact instead.

PUAMetadata Schema

When publishing a TATST:PUA attestation, the optional pua_info field carries rich software metadata. This field is only valid when artifact_type == FILE and is ignored (rejected) for any other artifact type.

type PUAMetadata struct {
    // SoftwareName is the display name (e.g. "SpeedBooster Pro")
    SoftwareName    string      `json:"software_name,omitempty"`

    // Vendor is the publisher / code-signing entity
    Vendor          string      `json:"vendor,omitempty"`

    // Version is the specific version where PUA behaviour was observed
    Version         string      `json:"version,omitempty"`

    // InstallerSHA256 is the SHA-256 of the installer bundle
    // (may differ from the payload / extracted PE sha256)
    InstallerSHA256 string      `json:"installer_sha256,omitempty"`

    // Behaviors is a bitmask of PUABehavior flags (see table below)
    Behaviors       PUABehavior `json:"behaviors,omitempty"`

    // BehaviorNotes — free-text elaboration (max 512 bytes, no HTML)
    BehaviorNotes   string      `json:"behavior_notes,omitempty"`

    // DetectionNames — cross-reference with AV/EDR detection names
    DetectionNames  []string    `json:"detection_names,omitempty"`
}

JSON Example

{
  "artifact_type":    "FILE",
  "artifact_sha256":  "4a5b6c7d...",
  "raw_value":        "SpeedBoosterPro_v3.2_setup.exe",

}

PUABehavior Bitmask Flags

The PUABehavior field is a bitmask — combine multiple flags with bitwise OR. The value 66 in the example above is BUNDLED_ADWARE (1) | CRYPTOMINER_PUA (64) = 65 — wait, let's be precise:

Flag NameValue (decimal)HexDescription
NONE00x000No specific behaviour flags set
BUNDLED_ADWARE10x001Silently installs ad-injection components alongside the main software
BROWSER_HIJACK20x002Modifies browser homepage, new-tab page, or default search engine without clear consent
FAKE_AV40x004Reports false positives to coerce purchase or upgrade ("scareware")
REGISTRY_CLEANER80x008Deceptive registry optimiser claiming to fix fabricated issues
DATA_HARVESTING160x010Collects and exfiltrates user behaviour or PII without meaningful consent
TOOLBAR320x020Installs unwanted browser toolbar without clear user consent
CRYPTOMINER_PUA640x040Covertly uses CPU/GPU cycles for cryptocurrency mining
REMOTE_ACCESS1280x080Includes undisclosed remote access capability (TeamViewer-style RAT-lite)
AUTORUN2560x100Persists via Windows autorun, scheduled task, or startup folder without disclosure
BUNDLED_INSTALL5120x200Silently installs additional third-party software during setup

// Fake AV + data harvesting: 4 + 16 = 20
"behaviors": 20

// Covert miner + autorun + browser hijack: 64 + 256 + 2 = 322
"behaviors": 322

// Full spyware toolkit: all flags except NONE = 1+2+4+8+16+32+64+128+256+512 = 1023
"behaviors": 1023

PUA CLI Examples

Attest a PUA installer file

# Hash the file first
SHA=$(sha256sum SpeedBoosterPro_v3.2_setup.exe | awk '{print $1}')

# Publish attestation
threatattestd tx attestation publish \
  --artifact-type FILE \
  --artifact-sha256 $SHA \
  --raw-value "SpeedBoosterPro_v3.2_setup.exe" \
  --severity LOW \
  --confidence 88 \
  --ttl 2592000 \
  --description "Installer bundles browser hijacker + covert cryptominer" \
  --category "TATST:PUA" \
  --from alice \
  --chain-id threatattest-1 \
  --fees 500utatst

Using attest-file convenience command

threatattestd attest-file SpeedBoosterPro_v3.2_setup.exe \
  --severity LOW \
  --confidence 88 \
  --ttl 2592000 \
  --description "Bundles browser hijacker and covert miner" \
  --category "TATST:PUA" \
  --output pua-attestation.json

PHISHING_URL Category

TATST:PHISHING_URL is used when a specific URL endpoint serves or redirects to a phishing page. The artifact is of type URL, and the SHA-256 is computed over the normalized URL (same normalization as other URL attestations: lowercase scheme/host, strip default ports, sort query params, strip fragment).

When PHISHING_URL differs from PHISHING

The original TATST:PHISHING category is unconstrained and can be applied to FILE, URL, IPV4, or DOMAIN artifacts. PHISHING_URL explicitly signals that:

  • The artifact is a URL
  • The phishing vector is URL-specific (a path, form, or redirect on that URL)
  • The rest of the domain may not be involved

The browser extension queries for PHISHING_URL when checking page URLs and applies a HIGH-severity warning regardless of the attestation's recorded severity.

PHISHING_SITE Category

TATST:PHISHING_SITE attests that an entire domain is operated as a phishing platform. Use a DOMAIN artifact type — the normalized domain is the artifact, and the SHA-256 covers the domain bytes. This category can also be applied to a URL artifact if the phishing operator is identified by their URL structure.

✅
Browser extension behaviour When the extension detects any navigation to a domain that has an active TATST:PHISHING_SITE DOMAIN attestation, it immediately shows a HIGH-priority "Phishing Site" banner with Block/Allow options, regardless of the specific URL path being loaded.

ADWARE Category

TATST:ADWARE covers domains and URLs associated with the distribution of adware software or the delivery of intrusive/deceptive advertising. This includes:

  • Download portals that bundle adware with legitimate software installers
  • CDN domains serving adware JavaScript payloads
  • Domains associated with browser-hijacking software distribution
  • Ad injection domains embedded in compromised websites

Note that adware software files should use TATST:PUA on a FILE artifact. TATST:ADWARE on DOMAIN/URL artifacts describes the infrastructure side of the adware ecosystem.

ℹ️
Severity guidance Adware domains are typically attested at LOW–MEDIUM severity. If the adware domain is also distributing malware (e.g. drive-by downloads), use TATST:ADWARE combined with TATST:MALWARE and raise severity to HIGH or CRITICAL accordingly.

MALVERTISING Category

TATST:MALVERTISING covers advertising infrastructure domains and URLs that have been observed distributing malware through ad creatives, forced redirects, or exploit-kit delivery chains. Malvertising is distinct from adware in that:

AspectADWAREMALVERTISING
Primary risk Unwanted software installation, intrusive ads Malware delivery, exploit-kit landing
Severity LOW – MEDIUM MEDIUM – HIGH
Typical victim action Clicks install or visits domain Passive — drive-by via ad impression
Infrastructure type Download portals, PUA bundlers Ad networks, CDNs, redirect chains

Category ↔ Artifact Type Constraints

The chain enforces category-to-artifact-type constraints at the ValidateBasic level. Attempting to publish a constrained category with an invalid artifact type will be rejected with error code 46 (ErrCategoryArtifactMismatch).

Category FILE (1) URL (2) IPV4 (3) DOMAIN (4) Constraint source
TATST:MALWARE ✅✅✅✅ Unconstrained
TATST:PHISHING ✅✅✅✅ Unconstrained (legacy)
TATST:C2 … TATST:BACKDOOR ✅✅✅✅ Unconstrained
TATST:PUA ✅❌❌❌ CategoryArtifactConstraints["TATST:PUA"]
TATST:PHISHING_URL ❌✅❌✅ CategoryArtifactConstraints["TATST:PHISHING_URL"]
TATST:PHISHING_SITE ❌✅❌✅ CategoryArtifactConstraints["TATST:PHISHING_SITE"]
TATST:ADWARE ❌✅❌✅ CategoryArtifactConstraints["TATST:ADWARE"]
TATST:MALVERTISING ❌✅❌✅ CategoryArtifactConstraints["TATST:MALVERTISING"]

Validation implementation

// types/types.go
func IsCategoryValidForArtifact(cat string, at ArtifactType) bool {
    allowed, constrained := CategoryArtifactConstraints[cat]
    if !constrained {
        return true  // unconstrained categories always pass
    }
    for _, a := range allowed {
        if a == at { return true }
    }
    return false
}

// msgs/msgs.go — ValidateBasic loop
for _, cat := range m.ThreatCategories {
    if !types.IsCategoryValidForArtifact(cat, m.ArtifactType) {
        return types.ErrCategoryArtifactMismatch
    }
}

The existing attest-file command now accepts PUA-specific flags when the category includes TATST:PUA:

threatattestd attest-file [file] \
  --severity  \
  --confidence <0-100> \
  --ttl  \
  --description  \
  --category "TATST:PUA" \
  # PUA-specific flags (all optional):
  --pua-software-name         # Display name of the software

CLI: attest-url (new command)

The new attest-url command is a convenience wrapper for URL attestations with phishing/malvertising categories pre-configured:

threatattestd attest-url [url] [flags]

Flags:
  --severity                 Severity (default MEDIUM)
  --confidence         <0-100>      Confidence score (default 85)
  --ttl                    TTL (default 604800 = 7 days)
  --description               Description (max 1024 bytes)
  --category               Threat categories (default TATST:PHISHING_URL)
  --tags                   Tags
  --attester                  Bech32 attester address
  --output               Output file (default url-attestation.json)
  --chain-id                    Chain ID (default threatattest-1)
  --dry-run                         Print spec without writing

CLI: attest-domain (new command)

The new attest-domain command creates DOMAIN artifact attestations, optimized for adware/malvertising/phishing-site use cases:

threatattestd attest-domain [domain] [flags]

Flags:
  --severity                 Severity (default MEDIUM)
  --confidence         <0-100>      Confidence score (default 80)
  --ttl                    TTL (default 2592000 = 30 days)
  --description               Description (max 1024 bytes)
  --category               Threat categories (default TATST:ADWARE)
  --tags                   Tags
  --attester                  Bech32 attester address
  --output               Output file (default domain-attestation.json)
  --chain-id                    Chain ID (default threatattest-1)
  --dry-run                         Print spec without writing

The command prints the normalized domain and its SHA-256 alongside the
Next Steps instructions for broadcasting via 'tx attestation publish'.
